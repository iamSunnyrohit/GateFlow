# 🔄 Progress 2.4 — Persistent Route Loading

[← Back to GateFlow README](../../README.md) · [← Progress 2.3](2.3-postgresql-integration.md) · [Next: Milestone 3 →](../../README.md)

## Overview

This stage connected PostgreSQL persistence with GateFlow's runtime route registry.

The gateway now loads saved route configurations from the database during initialization. This means route registrations are not lost when the gateway container restarts.

This completes the second major milestone: dynamic route management with database-backed persistence.

## Objectives

- Load route configurations from PostgreSQL during gateway initialization.
- Keep the runtime route registry synchronized with persisted configuration.
- Save newly registered routes to the database.
- Preserve route configuration across gateway restarts.
- Verify that persisted routes remain usable after restarting the gateway.

## Architecture

```text
             Gateway Startup
                   |
                   v
          Database Initialization
                   |
                   v
          Read Stored API Routes
                   |
                   v
          Populate Route Registry
                   |
                   v
           Gateway Ready
                   |
                   v
           Incoming Requests
                   |
                   v
          Match and Forward Route
```

## Implementation Details

### Database initialization

The database initialization logic is located in:

`gateway/database.py`

During gateway startup, the initialization process prepares the database and loads saved route configurations.

### Route persistence

The `api_routes` table stores route definitions.

When an administrator registers a route, the configuration is saved to PostgreSQL. The gateway can subsequently retrieve that configuration and make it available through its runtime route registry.

### Persistent route example

During development, the following route was registered:

```json
{
  "name": "persistent-product-route",
  "path": "/api/products-persistent",
  "service_url": "http://product-service:8003",
  "strip_prefix": "/api/products-persistent",
  "methods": ["GET"]
}
```

The route was saved successfully and appeared in the administrative route listing.

## Verification and Testing

The persistence behavior was verified through the following process.

### 1. Register a route

The `persistent-product-route` route was created through the administrative API.

### 2. Inspect the saved route

The route appeared in:

```bash
curl http://localhost:8000/gateway/admin/routes
```

### 3. Restart the gateway

```bash
docker compose restart gateway
```

### 4. Verify that the route survived the restart

After the gateway restarted, the route remained available.

The following request was successful:

```bash
curl http://localhost:8000/api/products-persistent
```

Observed response:

```json
{
  "service": "product-service",
  "status": "running"
}
```

This confirmed that the gateway successfully restored the saved route configuration after restarting.

## Result

GateFlow now supports persistent dynamic route management.

Route configurations are stored in PostgreSQL and loaded when the gateway starts. Administrators can register routes dynamically, and those routes remain available after a gateway restart.

**Milestone 2 is complete.**
